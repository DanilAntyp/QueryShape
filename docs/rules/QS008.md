# QS008 — Duplicate identical query

**Severity:** Warning · **Detects:** the same SQL shape with the same parameter values executed more than once in one scope.

## What it looks like

```csharp
var count = await db.Customers.Where(c => c.Country == country).CountAsync();     // from the controller
var total = await _pricing.QuoteAsync(country);                                    // runs the same Count inside
```

```
QS008 WARNING  Identical query executed 2 times: Customer from 2 places (CustomersController.cs:22 …, PricingService.cs:40 …)
```

## Why EF Core does this

EF Core does not cache query results. Every enumeration of a LINQ query sends the SQL to the database and materializes the rows again;
the change tracker only reconciles entity instances after the fact (and only for tracked entity queries). Two calls with identical
arguments therefore cost two round trips for one answer. Typical sources: a service method called twice in one request by different
callers, an `IQueryable` enumerated twice (`Count()` then `ToList()`, or two `foreach` loops), and helpers that re-load something the
caller already holds.

## Fix

- Run the query once and pass the result down, or memoize it for the lifetime of the request (a scoped service works well).
- For `Count()` + `ToList()` on the same queryable: materialize with `ToListAsync()` and use `.Count` on the list.
- For `Find`-style lookups, `DbContext.Find` returns the tracked instance without a query when it is already loaded.

## Notes

- Parameters are compared by a hash of names and values; values themselves are never stored unless `IncludeParameterValues` is on.
- Different parameter values for the same shape are [QS001](QS001.md)'s domain.
