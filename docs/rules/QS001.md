# QS001 — N+1 query

**Severity:** Error · **Detects:** the same SQL shape executed at least `NPlusOneThreshold` (default 5) times in one scope with different parameter values.

## What it looks like

```csharp
var customers = await db.Customers.ToListAsync();
foreach (var customer in customers)
{
    customer.Orders = await db.Orders.Where(o => o.CustomerId == customer.Id).ToListAsync();   // runs once per customer
}
```

```
QS001 ERROR  N+1 query: Order by CustomerId executed 10 times at OrderService.cs:42 OrderService.GetAll
  fix  Add .Include(c => c.Orders) to the Customer query at OrderService.cs:40 OrderService.GetAll
```

## Why EF Core does this

EF Core translates each LINQ query into exactly one SQL statement at the moment the query is enumerated. It has no view of the C# loop
around it, so it cannot batch iterations: every `ToListAsync()` inside the loop is a separate round trip with its own network latency.
The cost is proportional to the number of parents, so the page that is fast with ten customers is slow with a thousand.

QueryShape recognises the pattern from the shape: one statement, many executions, different arguments. When the expression tree shows a
filter on a foreign key (`o.CustomerId == …`) or a primary key (`c.Id == …`) compared to a parameter, the diagnosis names the relationship.

## Fix

- **Eager load** on the parent query: `db.Customers.Include(c => c.Orders)`. One statement (or two with `AsSplitQuery()` when several collections are included).
- **Project** what you need instead of loading entities: `db.Customers.Select(c => new { c.Name, OrderCount = c.Orders.Count })`.
- **Batch** when there is no navigation: collect the keys, then `db.Orders.Where(o => ids.Contains(o.CustomerId))`.
- Avoid lazy-loading proxies in request paths; they turn every navigation access into this pattern.

When the call site is known and the file is readable, QueryShape emits a unified diff that inserts the `Include` before the terminal operator (`ToListAsync()`).

## Notes

- Executions with **identical** parameters are not N+1; they are reported by [QS008](QS008.md).
- Raw SQL loops (Dapper, `FromSqlRaw`) are detected too, with a generic set-based fix because there is no expression tree.
- Threshold: `QueryShapeOptions.NPlusOneThreshold`.
