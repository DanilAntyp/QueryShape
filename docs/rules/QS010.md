# QS010 — Raw SQL with string concatenation

**Severity:** Error (security) · **Detects:** raw SQL commands in one scope whose texts differ only in literal values, the fingerprint of values concatenated into SQL.

## What it looks like

```csharp
foreach (var name in names)
    await db.Customers.FromSqlRaw($"SELECT * FROM Customers WHERE Name = '{name}'").ToListAsync();
```

```
QS010 ERROR  Raw SQL built from values: 3 text variants of "SELECT * FROM Customers WHERE Name = ?" at BadEndpoints.cs:112 BadEndpoints.Map
  fix  Pass values as parameters: FromSql($"... WHERE Name = {name}") / FromSqlInterpolated, FromSqlRaw("... {0}", name), or Dapper's anonymous parameter object
```

## Why EF Core does this

`FromSqlRaw` executes the string it is given. When the value is interpolated into that string before the call, it becomes part of the SQL text:
a name containing `'` breaks the statement and a crafted one changes it (SQL injection). The database also sees a *new* statement for every value,
so nothing is cached. EF Core's own analyzer (EF1002) warns about interpolated `FromSqlRaw`; QueryShape catches the runtime result, including Dapper and
hand-written commands through `QueryShapeDbConnection`.

## Fix

- `FromSql($"SELECT * FROM Customers WHERE Name = {name}")` (EF Core 7+) or `FromSqlInterpolated`: every hole becomes a `DbParameter`.
- `FromSqlRaw("SELECT * FROM Customers WHERE Name = {0}", name)`: placeholders plus arguments, never a pre-formatted string.
- Dapper: `connection.QueryAsync<Customer>("... WHERE Name = @name", new { name })`.

## Notes

- Detection compares texts after replacing string and numeric literals with `?`; a single execution cannot be judged and is not reported.
- Parameterized raw SQL (same text, different parameter values) is never flagged; loops over it are [QS001](QS001.md)'s concern.
