# QS006 — Missing split query candidate

**Severity:** Warning · **Detects:** two or more collection `Include`s loaded as a single query whose result is at least `CartesianMinimumRows` rows (default 50) and at least
twice the number of root entities, but has not (yet) reached the [QS002](QS002.md) threshold.

## What it looks like

```csharp
var customers = await db.Customers.Where(c => c.Id <= 15)
    .Include(c => c.Orders.Where(o => o.Total >= 40))
    .Include(c => c.Addresses)
    .ToListAsync();
```

```
QS006 WARNING  Split query candidate: 2 collection includes (Orders, Addresses) in one query, 60 rows for 15 Customer entities at BadEndpoints.cs:70 BadEndpoints.Map
```

## Why EF Core does this

Same mechanism as QS002: several collections in one SELECT are LEFT JOINed and the row count becomes the *product* of the collection sizes per root.
With small collections the product is tolerable today, which is why this is a Warning: the multiplication grows with the data, and the query that returns
60 rows in the test database returns thousands in production. EF Core itself logs `MultipleCollectionIncludeWarning` for this pattern.

## Fix

- `AsSplitQuery()` on the query, or `UseQuerySplittingBehavior(QuerySplittingBehavior.SplitQuery)` for the whole context.
- Filtered includes (`Include(c => c.Orders.Where(...))`) reduce the factor but do not remove the multiplication.
- Project instead of including when the caller only needs counts or a few columns.

## Notes

- Silent when the result is small (below `CartesianMinimumRows`), when rows are less than twice the roots (every root with two children multiplies a little; that alone is not a finding),
  or when the query already splits. When the root count cannot be estimated, EF Core's own `MultipleCollectionIncludeWarning` plus a non-tiny result is enough.
- Thresholds: `CartesianExplosionFactor`, `CartesianMinimumRows`.
