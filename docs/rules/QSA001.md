# QSA001 — LINQ operator after ToList()/ToArray() on an EF Core query (analyzer)

**Kind:** Roslyn analyzer (`QueryShape.Analyzers` package), Warning at compile time · **Detects:** `Where`, `First`, `Single`, `Last`, `Any`, `All`, `Count`, `Take`, `Skip`, `OrderBy`, `Min`/`Max`/`Sum`/`Average` applied directly to the result of `ToList()`, `ToArray()`, `ToListAsync()` or `ToArrayAsync()` on an `IQueryable` (a `DbSet` or any EF Core query).

## What it looks like

```csharp
var recent = db.Orders.ToList().Where(o => o.PlacedAt > since).Take(10);
//                     ^^^^^^^^ QSA001: 'Where' runs in memory because 'ToList' already loaded every row of the EF Core query
```

## Why this needs a compile-time check

`ToList()` executes the query: EF Core translates whatever is *before* it and loads every row. Everything after it is LINQ-to-Objects on a list,
so the `Where` never reaches EF Core and no runtime hook can see it; QueryShape's runtime rule QS003 cannot report it, and QS004 only sees an
unbounded query. The compiler can see it, which is why this lives in an analyzer.

## Fix

Move the operator before the materializer: `db.Orders.Where(o => o.PlacedAt > since).Take(10).ToList()`.

If the filter genuinely cannot be translated, say so with `AsEnumerable()`: `db.Orders.AsEnumerable().Where(o => Helper(o))`. The analyzer never flags `AsEnumerable()`, because it is the documented way to opt into client evaluation.

## Notes

- Only direct chains are flagged. A list stored in a variable and filtered later is not, because the list may be reused; the runtime rules cover what happens then.
- `Select` after `ToList()` is not flagged: projecting a materialized list is not a translation loss by itself.
- Install with `dotnet add package QueryShape.Analyzers`; it has no runtime dependency and no effect on the build output.
