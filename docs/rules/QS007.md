# QS007 — `Contains` on large collection

**Severity:** Warning · **Detects:** a query whose collection parameter (JSON array for SQL Server/SQLite, array for PostgreSQL) or inline `IN (...)` list has more than `ContainsCollectionThreshold` (default 500) elements.

## What it looks like

```csharp
var ids = Enumerable.Range(1, 600).ToList();
var lines = await db.OrderLines.Where(l => ids.Contains(l.Id)).ToListAsync();
```

```
QS007 WARNING  Contains over 600 values on the OrderLine query (threshold 500) at BadEndpoints.cs:78 BadEndpoints.Map
```

## Why EF Core does this

`Where(x => list.Contains(x.Id))` can only be translated by shipping the list to the database. EF Core 8+ sends it as a single JSON parameter and unpacks it
with `OPENJSON` (SQL Server) or `json_each` (SQLite); Npgsql sends an array and compares with `= ANY(...)`; older compatibility levels inline one literal per
value. In every case the optimizer has no statistics for the values, the statement or parameter grows with the list (SQL Server caps parameters at 2 100,
and each distinct inline list is a new plan to compile), and the whole list crosses the network on every call.

## Fix

- If the values come from the database, express the filter as a subquery or join instead of round-tripping them through memory:
  `db.OrderLines.Where(l => db.Orders.Where(o => o.CustomerId == id).Select(o => o.Id).Contains(l.OrderId))`.
- If they truly originate on the client (file import, external API): chunk (`ids.Chunk(500)`) or bulk-insert into a temporary table and join.

## Notes

- The count comes from the actual parameter value (JSON array length / array count) or the inline list, never from source code.
- Threshold: `QueryShapeOptions.ContainsCollectionThreshold`.
