# QS009 — Query in loop over navigation

**Severity:** Warning · **Detects:** one call site (file + member) issuing at least `NPlusOneThreshold` queries of two or more shapes, each shape repeated, within one scope.

## What it looks like

```csharp
foreach (var order in orders)
    result.Add(await Summaries.ForOrderAsync(db, order));       // helper runs 2 queries per order

static async Task<object> ForOrderAsync(ShopDbContext db, Order order)
{
    var customer = await db.Customers.FirstAsync(c => c.Id == order.CustomerId);
    var lines = await db.OrderLines.CountAsync(l => l.OrderId == order.Id);
    ...
}
```

```
QS009 WARNING  Queries in a loop: Summaries.ForOrderAsync issued 16 queries of 2 shapes (Customer, OrderLine) in one scope
```

## Why EF Core does this

Each call to the helper is, to EF Core, an unrelated query: it compiles once per shape and executes once per call. The loop multiplies every round trip
in the helper by the number of items. Unlike a plain N+1 ([QS001](QS001.md)), the per-iteration queries have *different* shapes, so no single `Include`
removes them; the fix is structural.

## Fix

- Load what the helper needs for **all** items before the loop: `Include`/`Select` on the outer query, or one batched query per shape
  (`db.OrderLines.Where(l => orderIds.Contains(l.OrderId)).GroupBy(l => l.OrderId).Select(...)`) turned into a dictionary with `ToDictionaryAsync`.
- Pass the pre-loaded data into the helper; keep the helper free of `DbContext` access.

## Notes

- Requires call sites: on in tests (`CaptureCallSites`), or EF Core's `TagWithCallSite()` in production. A tag knows only file and line, so tagged
  queries group by line: two different tagged queries in one file are not treated as one loop body.
- A shape that is an N+1 on its own is also reported as [QS001](QS001.md) with its Include fix; QS009 names those shapes and reports the loop that issues them together.
- Threshold: `QueryShapeOptions.NPlusOneThreshold`.
