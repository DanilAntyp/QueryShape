# QS003 — Client-side evaluation

**Severity:** Error · **Detects:** a call to your own code inside a query's projection that EF Core cannot translate and runs once per row in memory.

## What it looks like

```csharp
var rows = await db.Orders
    .Select(o => new OrderRow { Id = o.Id, Label = PriceFormatter.Format(o.Total) })   // Format runs on the client, per row
    .ToListAsync();
```

```
QS003 ERROR  Client-side evaluation: PriceFormatter.Format(Decimal) runs in memory for every Order row at OrdersController.cs:31 OrdersController.List
```

## Why EF Core does this

EF Core can translate the methods it knows: LINQ operators, common `string`/`DateTime`/`Math` members, `EF.Functions`, and methods you
map with `HasDbFunction`. Anything else has no SQL equivalent. Since EF Core 3.0, an untranslatable call in `Where`, `OrderBy`, `GroupBy`
or a join throws `InvalidOperationException` at compile time. In the **final `Select`** it does not throw: EF Core fetches the columns the
call needs and evaluates the call on the client for every row after the SQL returns. That is convenient and silent, which is the problem:
the work no longer uses indexes, runs per row, and if the method touches a navigation it may issue one extra query per row.

## Fix

- Make the boundary explicit: project raw columns, then `AsEnumerable()` (or materialize) and apply the method in memory.
  ```csharp
  var rows = (await db.Orders.Select(o => new { o.Id, o.Total }).ToListAsync())
      .Select(x => new OrderRow { Id = x.Id, Label = PriceFormatter.Format(x.Total) });
  ```
- If the database can do the work, map it: `modelBuilder.HasDbFunction(() => PriceFormatter.Format(default))` or rewrite with `EF.Functions`.
- If the method exists only for display, move it to the view layer.

## Notes

- Detection works on the pre-translation expression tree: a method call is reported when its declaring type is outside `System*`, `Microsoft.*`
  and provider namespaces and is not a mapped DbFunction. See [ADR-0003](../adr/0003-client-evaluation-detection.md).
- `AsEnumerable()`/`ToList()` **before** `Where`/`Select`/`OrderBy` cannot be observed at runtime: the LINQ-to-Objects operators never reach EF Core.
  Their symptom, an unfiltered query that loads everything, is reported by [QS004](QS004.md).
