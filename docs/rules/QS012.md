# QS012 — Synchronous query on an async path

**Severity:** Warning · **Detects:** a command executed through EF Core's synchronous API inside a scope whose host declared itself asynchronous
(`app.UseQueryShape()` sets that on every request scope).

## What it looks like

```csharp
app.MapGet("/customers", (ShopDbContext db) =>
{
    var customers = db.Customers.AsNoTracking().Where(c => c.Country == "DE").ToList();
    return Results.Ok(customers);
});
```

```
QS012 WARNING  Blocking query: Customer ran synchronously once in an async request, blocking the thread for 12 ms at CustomersController.cs:31 CustomersController.List
  fix  Await the async overload of the terminal operator (ToListAsync, FirstOrDefaultAsync, CountAsync, AnyAsync…)
```

## Why this matters

The request is served on a thread-pool thread shared with every other request in flight. `ToList()`, `First()`, `Count()` and `SaveChanges()`
hold that thread while the database works; the async overloads return it to the pool and take one back when the answer arrives. In isolation
nothing looks wrong — the query takes exactly as long either way, and a local test with one request at a time cannot tell the difference. The
cost appears under concurrency: requests queue for threads that are all parked on the database. The thread pool does grow, but beyond its
minimum it injects roughly one thread per second, so a burst is served at that rate rather than at the rate the database could answer.

This is why the rule needs the host to say it is asynchronous. Synchronous EF Core is correct and normal in a console tool, a migration, a batch
job or a plain unit test, and QueryShape says nothing there.

## Fix

- Await the async overload: `await query.ToListAsync(cancellationToken)`, `await db.SaveChangesAsync(cancellationToken)`.
- If the call is inside a synchronous method, make that method `async` up to its caller. Do not bridge with `.Result` or `.Wait()`: that blocks
  the same pooled thread one frame higher and can deadlock where a synchronization context is present.
- Pass the request's `CancellationToken` while you are there, so an abandoned request stops costing database work.

## Notes

- No unified diff. EF Core's expression tree stops before the terminal operator, so QueryShape can see that a command ran synchronously but not
  whether the source says `ToList()`, `First()` or `Count()`; and awaiting also changes the enclosing method's signature. The fix is marked
  partial and carries the manual step (ADR-0015).
- One finding per shape and call site, with the number of executions and the summed blocked time. A synchronous N+1 reports once here and once
  as [QS001](QS001.md).
- Any host can opt in: annotate the scope with `QueryShapeScope.AsyncHostAnnotation` (`host.async` = `true`) in a message consumer or a
  background service. Inner scopes inherit the declaration from the scope that opened around them.
- The rule reads `CapturedCommand.IsAsync`, which comes from EF Core's own `CommandEventData`; it is not inferred from the thread or the
  synchronization context.
